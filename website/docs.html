Quickstart

Install CoreYOLO, then train a nano model on Roboflow YOLO labels.

pip install coreyolo
from coreyolo import Detector

model = Detector("n")              # GELAN (default)
# model = Detector("n", family="e2e")
model.train(data="data.yaml", epochs=100, imgsz=640)
model.save("weights/app.coreyolo")
results = model.predict("photo.jpg", classes="person")
model.export(imgsz=640)           # FP16 + palettize; palettize=False to skip
coreyolo dummy-data --out datasets/dummy
coreyolo train --data datasets/dummy/data.yaml --model n --family gelan --epochs 20 --imgsz 320
coreyolo train --data datasets/dummy/data.yaml --model n --family e2e --epochs 20 --imgsz 320
coreyolo val --data datasets/dummy/data.yaml --weights runs/detect/train/weights/best.pt
coreyolo export --weights runs/detect/train/weights/best.pt --imgsz 320
coreyolo predict --weights runs/detect/train/weights/best.mlpackage --source photo.jpg --device auto

Detector("n") builds an untrained GELAN nano graph. Pass family="e2e" for the NMS-free graph. Detector("weights/app.coreyolo") or a .mlpackage loads a trained artifact. Do not pass Ultralytics yolov9t.pt into Detector() — that layout is rejected. from coreyolo import YOLO still works as an alias.

Python SDK

from coreyolo import Detector, Result. Methods: train, val, predict, export, save, info, dummy_data. Webcam: model.predict(0) on a Mac. That is not the iPhone runtime. YOLO is a compatibility alias; YOLO is a trademark of its owners.

Native checkpoints are tagged format: "coreyolo" with stem.* / head.* tensors. Suffix may be .coreyolo or .pt.

CLI

coreyolo train | val | predict | export | convert | coco | dummy-data

Device: --device gpu (default) is PyTorch MPS / Core ML CPU_AND_GPU. auto tries Neural Engine first on a .mlpackage. Also ane, all, cpu.

Graph: --family gelan (default, YOLOv9 GELAN; n = yolov9t), --family dfl (C2f + host NMS), or --family e2e (C3k2 + C2PSA, NMS-free). Old 9 / 8 / 26 flags still load.

Activation: --act relu (default, ANE). silu is only for converted YOLOv9 tensors — do not swap it on those checkpoints. Also star (StarReLU), gelu, hardswish.

GELAN, DFL, and E2E

GELAN is the default detect graph: ELAN1 / RepNCSPELAN4 / SPPELAN, Distribution Focal Loss, decoded xywh, class-aware NMS on the host. Scale n matches Ultralytics yolov9t. Core ML layout (1, 4+nc, N). Optional one-time remap from yolov9t.pt.

DFL is the older C2f + SPPF graph with the same DFL head.

E2E is C3k2 + C2PSA with a dual TAL head and NMS-free top-300 at inference. Core ML layout (1, 300, 6) as xyxy, conf, cls. Train from scratch: --family e2e or --recipe coco-n-e2e.

Export

coreyolo export --weights weights/app.coreyolo --imgsz 640
coreyolo export --weights weights/app.coreyolo --imgsz 640 --no-palette
coreyolo export --weights weights/app.coreyolo --imgsz 640 --int8

Default export is an FP16 ML Program (iOS 16 / macOS 13): fused Conv–BN, cached DFL anchors, MIL cleanup passes. ReLU, ReLU6, StarReLU, and HardSwish convert with CPU_AND_NE so the graph stays ANE-legal, then 8-bit k-means palettize. --int8 is linear weight quant instead of palettes. Converted SiLU YOLOv9 packages still prefer GPU — train ReLU from scratch for Neural Engine.

Python: model.export(imgsz=640) or palettize=False. Package metadata records optimize (palettize8 / fp16 / int8) and preferred_compute (ane or gpu).

Labels

Roboflow YOLO export: data.yaml plus train|valid/{images,labels}. Each detect line is normalized class xc yc w h. Segmentation uses polygons. The loader accepts list or dict names, val or valid.

Segmentation

coreyolo dummy-data --out datasets/dummy-seg --segment
coreyolo train --data datasets/dummy-seg/data.yaml --model n --task segment --epochs 20 --imgsz 320

GELAN is the supported seg graph. Mosaic is off so polygons stay valid. Core ML writes three outputs: detections, mask coefficients, proto.

COCO

coreyolo coco --out datasets/coco --download
coreyolo coco --out datasets/coco --splits val --max-images 512 --no-download
coreyolo train --recipe coco-n-fast
coreyolo train --recipe coco-n-e2e

Optional bootstrap, once, not in the app. Remaps names only — converted tensors stay Ultralytics (AGPL-3.0):

coreyolo convert --weights yolov9t.pt --out weights/coreyolo-n-coco.coreyolo
coreyolo convert --weights yolov9c.pt --out weights/coreyolo-l-coco.coreyolo

Ultralytics YOLOv9 is a separate project. Its source is open under AGPL-3.0 (view, share, modify, distribute).

The AGPL catch: if you modify YOLOv9 or use it in a network service (SaaS) so users interact with it over a network, you typically must release your whole application under AGPL-3.0.

Commercial / closed internal use: a commercial product or a closed-source internal enterprise tool that uses Ultralytics YOLOv9 without publishing that source usually needs a commercial license from Ultralytics. coreyolo convert remaps tensor names; it does not relicense those weights. Fine-tunes and Core ML exports of converted files stay AGPL-3.0. Do not rehost them as MIT.
